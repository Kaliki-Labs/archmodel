# PR comment image: attached locally with `gh`, not drawn or hosted by CI

## Context

A PR comment can only show an image from a URL, and Actions artifacts have no
public URL. The first design (ADR 0010) had CI commit the PNG to an orphan
`archmodel-assets` branch and rewrite a placeholder in the Markdown. That costs
`contents: write`, a branch of binaries to prune, and one-time setup.

`gh` 2.99+ has `gh pr comment --attach <file>`, which uploads the file as a
native GitHub attachment and rewrites `![alt](<file>)` in the body. We tried it
in a Workflow on a private scratch repository (gh 2.102 on the runner):

- With `GITHUB_TOKEN` (`pull-requests: write`) the upload fails with
  `unsupported authentication type`. The build and diff steps were fine.
- The same command with a user token works and yields a
  `github.com/user-attachments/assets/...` URL. On a private repository an
  anonymous request to that URL returned 404.

The upload endpoint is undocumented, so a bot token may never be supported.

## Decision

**CI does not draw or host the image.** The Workflow builds both models, posts
the sticky comment (text plus the folded Mermaid version of the changed
subgraph), and uploads the Explorer as an artifact. It needs only
`pull-requests: write`, with no assets branch and no `sed`.

**The image is attached from a machine where `gh` runs as a person**, normally
the agent working on the PR, as `archmodel diff --image diff` followed by
`gh pr comment --body-file diff.md --attach diff.png`. The commands live in
`docs/ci-example.md` and are meant to be copied into agent instructions.

**`--image-url` defaults to the PNG's path relative to the `--markdown` file**
(its bare file name when the Markdown goes to stdout), instead of a placeholder.
That makes the command above work with no rewriting, and the Markdown renders
next to its image locally. `--image-url` stays for anyone hosting elsewhere.

## Why not the alternatives

- **Assets branch in CI**: works with `GITHUB_TOKEN`, but the cost above, and a
  binary history nobody wants. Still available through `--image-url`.
- **`--attach` in CI with a PAT or GitHub App token**: gives the nicest result
  but needs a secret someone must own and rotate, on an undocumented endpoint.
- **Commit the PNG to the PR branch** (generated by a pre-commit hook): the
  image goes stale against later commits, it pollutes the diff, and it needs
  cleanup after merge. Staleness would need its own check.
- **Mermaid only**: always works, and is what CI shows anyway, but it is a
  rougher drawing than the PNG.
- **Artifact link**: not inline.

## Consequences

- Without an agent or person attaching it, the PR has the text and Mermaid but
  no picture. That is acceptable: the image is a convenience, and `diff` is
  non-blocking.
- The attached image is a second comment next to the CI one. Keeping to a single
  comment means deleting earlier `<!-- archmodel-diff -->` comments first and
  giving the CI comment a different sticky header or skipping it; the docs say
  how, and nothing automates it. `--edit-last` is unsafe (it edits the current
  user's last comment, which may belong to something else).
- Attachment URLs are unguessable and, in our test on a private repository, not
  readable anonymously. Public repositories were not tested.
- If GitHub later documents bot-token uploads, CI can attach the image itself
  and this ADR should be revisited; the relative default already supports it.
